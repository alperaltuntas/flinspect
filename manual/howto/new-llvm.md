# Port to a new LLVM

flang's parse-tree dump is a debugging aid with **no stability contract**;
clang's JSON AST schema also moves between releases. Track B's defense is not
hoping the formats hold — it is the conformance corpus, which turns "the
compiler updated" into a bounded checklist. (This workflow has been executed
for real: a with-sema format change was once localized to a single construct
in minutes.)

## 1. Regenerate the fixtures

With the new toolchain active:

```console
$ cd tests/f90 && ./gen_ptree_files.sh
```

The script regenerates every `*_ptree` fixture and stamps the new
`flang --version` into `tests/f90/PROVENANCE` — the version delta is itself
part of the record. (The C++ corpus has no committed dumps; its drift axis is
covered by re-running the clang-gated tests below.)

## 2. Read the diffs

```console
$ git diff tests/f90/
```

This is the **early-warning tier**. Because each fixture is one minimal
construct, whatever changed in the dump format shows up as diffs on exactly
the fixtures exercising the constructs that moved — the diff localizes the
break to named constructs before any code runs.

## 3. Run the suite; fix each break against its minimal example

```console
$ PYTHONNOUSERSITE=1 pytest            # + GROUNDLINE_CORPUS / clang++ for the gated tiers
```

The **contract tier** — extracted-IR and golden-Lean assertions — now tells
you which of those format changes actually broke extraction. Each failure
pairs with one fixture and, via `tests/f90/MANIFEST.md` (construct → fixture
→ parser code path), points at the frontend code to adapt. Fix format
adaptation *below the seam* only: the kernel IR and the printed Lean must come
out unchanged. A golden-Lean diff means the port changed the model, which is
no longer a port — stop and understand it.

## 4. Regenerate production and verify

```console
$ groundline kernel generate --kernels examples/turbo-stack.kernels.toml
$ groundline kernel verify   --kernels examples/turbo-stack.kernels.toml
```

The byte-diff gate is the acceptance test: after a pure format port, the
committed `Generated.lean` must match a fresh regeneration **byte for byte**,
and `GeneratedCpp.lean` must match in every def (its header comment re-stamps
the new clang version — that one diff is by design and gets committed).
`lake build` then re-checks every theorem against the regenerated defs.

## 5. Update the provenance records

Commit together: the regenerated fixtures, the new `PROVENANCE` stamp, any
frontend adaptations, and the re-stamped `GeneratedCpp.lean` header. The
quickstart's committed dump (`examples/quickstart/toy_kernel_ptree` +
`PROVENANCE`) follows the same convention — regenerate it in the same pass.

!!! note "Corpus dumps are a separate pipeline"

    The production with-sema corpus (the MOM6 build's `*_ptree` files) is
    generated by the model's own build system, not by this repository —
    regenerating it under the new LLVM is a build-pipeline task. Until it is
    regenerated, the old-format corpus plus the new-format frontend is
    exactly the mismatch the fixtures exist to catch, so do the fixture pass
    first.
